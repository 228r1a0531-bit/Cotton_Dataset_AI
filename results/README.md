# Research artifacts

The dashboard reads local, Git-ignored artifacts from this directory. Add only
recorded measurements and cite any externally published benchmark.

| File | Required CSV columns or JSON fields |
| --- | --- |
| `research.json` | `classes` (four labels) |
| `dataset.csv` | `class,split,count`, one row per class and split |
| `training.json` | `configuration` (object), `status` (string) |
| `training.log` | Plain text. The dashboard displays the tail. |
| `history.csv` | `epoch,split,metric,value` |
| `comparisons.csv` | `comparison,variant,metric,value`. Use a comparison name displayed on the page. |
| `metrics.csv` | `metric,value` |
| `complexity.csv` | `model,training_seconds,parameters` |
| `confusion.csv` | `actual,predicted,count` |
| `roc.csv` | `class,fpr,tpr,auc` |
| `folds.csv` | `fold,metric,value` |
| `inference.json` | `classes` (four labels in checkpoint output order), `image_size` ([width, height]), `pixel_scale` (`0_255`, `0_1`, or `minus1_1`) |

For inference, install the optional machine learning dependencies and place a
trusted checkpoint at `checkpoints/classifier.keras` in the repository root.
The model must accept a single batch of RGB float32 images and return four
softmax probabilities. Preprocessing applies EXIF orientation, converts to RGB,
resizes directly with bilinear sampling, and uses the declared pixel scale.
Only connect checkpoints trained with that preprocessing.

## Files generated by Dataset & Training

**Save split metadata** writes `dataset.csv` and `splits.json`. The JSON includes
the local root, seed, target ratios, and relative path, label, and decoded-pixel
digest for every included sample. Counts in `dataset.csv` describe eligible
split members after excluding duplicates and conflicting labels.

Each training run gets its own `training_runs/<run-id>/` folder. It contains
the split snapshot, `training.json` (status, settings, class indices, best epoch,
and held-out test metrics), `history.csv`, and `training.log`. Successful runs
also contain `classifier.keras` and `inference.json`. Upload & Classification
uses the newest completed run with those files unless a manual checkpoint is
configured at `checkpoints/classifier.keras` with `results/inference.json`.

New checkpoints use the ordered labels `bacterial_blight`, `curl_virus`,
`fusarium_wilt`, and `healthy`. The manifest records the model name,
`image_size: [224, 224]`, and `pixel_scale: "0_255"` because the model handles
rescaling internally. Older `baseline.keras` runs can still be installed as a
manual checkpoint with this manifest format.

## Model comparison dashboard

**Published Research** uses the version-controlled
`research/published_benchmarks.json`. Feature extraction and final
classification are distinct stages. `five_fold_accuracy` stores the five
supplied reference fold percentages.

**Our Experiment** reads `comparisons.csv`, `metrics.csv`, and `folds.csv`
from this directory and shows held-out accuracy from the newest completed
dashboard training run. For the comparison charts, a CSV metric value defaults
to a fraction (e.g. `0.9649`). Add a `unit` column with `percent` to use values
such as `96.49`. `metrics.csv` may include a `model` column to distinguish
multiple models. CSV downloads retain the data source and the evaluation
context. The camera button on each chart exports a PNG.

## Evaluation artifacts

A completed dashboard training run or an evaluation bundle may include:

| File | Contents |
| --- | --- |
| `metrics.csv` | Overall accuracy, macro precision, recall, F1, sensitivity, specificity, and macro one-vs-rest AUC when defined |
| `class_metrics.csv` | Per-class precision, recall, F1, sensitivity, specificity, and support |
| `confusion.csv` | Ground-truth and predicted class pairs with counts |
| `roc.csv` | One-vs-rest FPR, TPR, and AUC per eligible class |
| `predictions.csv` | Relative image path, digest, label, prediction, and probabilities by class |
| `complexity.csv` | Model, wall-clock fit seconds, parameter count, and checkpoint size in decimal MB |
| `folds.csv` | Measured fold number, metric, and fractional value |
| `comparisons.csv` | Measured ablation or paired-loss results |

Results from CLI protocols live under `results/evaluations/<id>/`. Their
`experiment.json` records the protocol and completion status. Individual
training trial artifacts are retained inside each CV or comparison bundle.
Rates are fractions. Macro averaging weights each class equally. Recall
and sensitivity use the same one-vs-rest definition. Specificity is
`TN / (TN + FP)`. AUC is omitted when a class has no positives or negatives.
